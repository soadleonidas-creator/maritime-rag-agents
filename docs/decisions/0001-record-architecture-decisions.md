# 1. Record architecture decisions

- **Date:** 2026-11-27
- **Status:** Accepted

## Context

This project is meant to show not only *what* was built but *why*. Tool choices (model provider, vector store, orchestration, cloud) involve trade-offs between cost, latency, reliability and operational effort.

## Decision

Every significant choice is recorded as a short decision record in `docs/decisions/`, numbered in order, using this template:

- **Context**: the problem and constraints
- **Options considered**: with pros and cons
- **Decision**: what was chosen
- **Consequences**: costs, risks, what to revisit later

## Consequences

Decisions can be reviewed and revisited. The log also serves as material for write-ups and interviews.
